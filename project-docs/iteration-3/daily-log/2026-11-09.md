## What-if simulator UI (#187)

- `libs/react-ui/src/lib/what-if-simulator/`: `WhatIfSimulator` composing
  `WhatIfSimulatorForm` (scenario name + holding symbol + drop-percentage
  inputs, client-side validation mirroring the server's

  `what-if.service.ts`'s `(0, 1]` decimal check exactly at both boundaries)
  and `WhatIfResultPanel` (before/after health score with severity dots,
  holding/portfolio value and allocation change, new/resolved/changed
  warnings), wired to `POST /api/v1/risk/what-if` via `runWhatIf()`.
- Caught and fixed a real bug before committing, not just reading the code:
  `what-if-simulator.client.ts` and its spec both imported `RiskApiEnvelope`
  and `RiskApiError` from `risk-dashboard.client.ts`, but neither was
  actually exported there - a compile error, not a style nit. `requestApi`
  (the shared GET-only helper) can't be reused here since `/risk/what-if` is
  a POST, and unlike every other route's generic client-facing error
  message, `RISK_WHATIF_INVALID_DROP`/`RISK_WHATIF_HOLDING_NOT_FOUND` are
  deliberately specific, safe, user-actionable text
  (`risk.controller.ts#postWhatIf`) that the UI is meant to show verbatim -
  so a bespoke envelope type/error class is the right design, it just
  needed to actually exist. Added `RiskApiEnvelope`/`RiskApiError` to
  `risk-dashboard.client.ts` (same Risk-feature folder, no shared-library
  change) rather than inventing a second copy.
- Verified field-for-field against the real backend: `RunWhatIfRequest`

  `WhatIfResult`, `WhatIfWarningSummary` against `RiskWarning`, and
  `scoreToSeverity`'s GREEN/YELLOW/RED boundaries (80/60) against
  `getOverallSeverity` in `risk-score.mapper.ts` - all match exactly.
