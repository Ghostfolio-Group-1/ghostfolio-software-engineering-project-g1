## PR 1 — Remaining Risk API routes (#24) — PR #222

Added the routes `/risk/thresholds[/:ruleKey]`, `/risk/target-allocation`,
and `/risk/warnings` to `risk.controller.ts`, wiring already-built mappers
(`risk-threshold.mapper.ts`, `target-allocation.mapper.ts`,
`risk-warnings.mapper.ts`) and the catch-all `RiskExceptionFilter` that were
drafted ahead of time, plus a `UserService` dependency for writes (rejected
while impersonating, per the contract doc). This completes the risk API
contract (#24).

- Caught and fixed 3 real bugs while verifying against the actual test run,
  not just reading the code:
  - A type error: `userSettings.xRayRules` (`XRayRulesSettings`, no index
    signature) isn't directly assignable to `toRiskThresholdsList`'s
    `Record<string, RuleSettings>` parameter — fixed with an explicit cast
    at the three call sites that index into it.
  - Two pre-existing test files (`risk.controller.routes.spec.ts`,
    `risk.e2e.spec.ts`) built `RiskController` through NestJS's testing
    module without providing every constructor dependency — missing
    `ConfigurationService`/`REQUEST` in one, `UserService` in the other —
    which failed every test in those files at DI-resolution time, not just
    the new ones. Fixed by adding the missing providers.
  - A wrong test expectation: `GET /risk/warnings` for a fully empty
    portfolio was asserted to return one RED warning ("0 cash / 0 portfolio
    value = 0, below the red minimum"), but `evaluateCashAllocation`
    deliberately returns `null` (`NO_DATA`) when portfolio value is 0 —
    already covered by `risk-evaluation.service.spec.ts`'s "reports every
    rule as NO_DATA for a fully empty portfolio" test. Fixed the assertion
    to expect `total: 0`, not the production code.
- Verified via `nx test api` scoped to the risk module: 680 passed (1
  pre-existing, unrelated skip). The only other failure in the full `api`
  suite is `tax-pdf-export.spec.ts`, which fails to compile over a missing
  `pdf-lib` dependency — pre-existing, outside the risk module, not touched.
- Lint: 0 errors on the `api` project.
