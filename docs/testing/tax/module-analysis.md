## Tax architecture to preserve

- `tax-data.service.ts`: tax-relevant and normal analysis eligibility, transaction history and chronology.
- `fifo-tax-lot.ts` / `fifo-realized-gain.ts`: account-scoped chronological lot consumption and sale-level fee allocation.
- `average-cost.ts` / `average-cost-realized-gain.ts`: user-and-asset average-cost pool, before/after transition, realized gains.
- `dividend-record.ts`: gross dividend, withholding, net dividend and separate activity fee; unknown remains `null`.
- `tax.service.ts`, `yearly-tax-summary.ts`: source orchestration, annual aggregation, historical currency conversion and completeness diagnostics.
- `tax-export.ts`, `tax-pdf-export.ts`: deterministic serializations of authoritative results; no new financial calculations.
- `tax.controller.ts`: authenticated public HTTP API; services are not automatically HTTP endpoints.
- `libs/react-ui/src/lib/*`: authenticated API clients, page states, display of exact decimal strings.

## Data and execution caveats

- Preserve decimal strings and `null` rather than converting unavailable finance values into zero or JS floating-point amounts.
- FIFO lot scope = user + account + asset; average-cost pool scope = user + asset. Do not silently treat them as identical.
- The UI must not supply average-cost individual lots when backend only provides FIFO lots.
- Historic October 29 Tax evidence (16 suites / 218 tests passed) is a separate baseline, **not** a November 13 execution result and **not** the count of the expanded present-day test inventory.
- Do not count the same test in multiple categories as independent results.
- Record specific executed commands, test pass/fail, commit, environment and CI links after any later runs.
