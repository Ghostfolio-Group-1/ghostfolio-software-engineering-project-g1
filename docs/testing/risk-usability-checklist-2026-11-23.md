## Regression tests added for the Fail -> Fixed rows

- `libs/react-ui/src/lib/risk-indicator/risk-indicator.spec.tsx` - `NO_DATA`'s
  expected colour updated to `#757575`; reverting the fix locally and
  re-running reproduces the old `#9e9e9e` failure (confirmed).
- `libs/react-ui/src/lib/risk-thresholds/risk-threshold-row.spec.tsx` and
  `risk-thresholds-page.spec.tsx` - aria-label selectors updated to the new
  readable text; reverting the fix locally breaks all 5 affected assertions
  (confirmed - the selector returns `null` and the subsequent interaction
  throws).
- `libs/react-ui/src/lib/target-allocation/target-allocation-form.spec.tsx` -
  now asserts each row's label includes its row number, not just that two
  (identical) labels exist; reverting the fix locally breaks this assertion
  (confirmed).
- `e2e/tests/risk-thresholds-usability.spec.ts` (new) - live browser
  coverage for #5, #6 and #8 against the real app and a real demo-stack
  database; reverting the fix for #5 locally and rebuilding the demo image
  reproduces a real `element(s) not found` Playwright failure (confirmed),
  not just a jsdom/mock failure.

All of the above were run both with the bug present (red) and with the fix
applied (green) before being left in the green state - "break it on
purpose, see it fail, restore" per the QA plan's "Real tests only" rule.
